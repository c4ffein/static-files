L'intérêt d'avoir présenté tout ça, c'est que c'est maintenant beaucoup plus simple pour nous de comprendre la distinction entre le harness et le modèle.

Dans un agent, encore une fois, le modèle, c'est la partie qui va uniquement faire de la prédiction du token suivant. Et le harness, c'est tout ce qu'il y a autour et qui va permettre, entre autres, d'interagir avec notre code base. Ce qu'il faut vraiment prendre en compte, c'est le fait que la majorité des entreprises qui fournissent des modèles fournissent également un harness complètement accordé à ce modèle.

Par exemple, si on prend Claude, on a tout intérêt à utiliser le harness Claude Code qui va généralement nous obtenir de meilleurs résultats. En preuve de ça, le 4 février 2026, GitHub a publié un article de blog en expliquant que c'était maintenant possible d'utiliser différents agents, et non plus seulement différents modèles, à l'intérieur de la majorité de leurs solutions.

C'est-à-dire que dans GitHub Copilot, on ne choisit plus seulement le modèle Claude derrière l'agent Copilot par défaut : on peut directement lancer Claude Code, ou Codex, dans GitHub, GitHub Mobile ou le GitHub Copilot de VS Code.

Il y avait déjà une extension Claude Code pour VS Code, mais il y a maintenant également la possibilité de travailler avec l'agent Claude Code directement depuis l'extension GitHub Copilot elle-même, et donc en utilisant le compte GitHub Copilot pour la consommation des tokens. Donc même là, on ne se contente plus du modèle : on prend le harness qui va avec.
